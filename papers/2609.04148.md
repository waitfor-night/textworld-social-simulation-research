## One-line takeaway

Terminal-Universe turns tool-use traces into replayable workspaces that can generate new, multi-round tasks instead of treating a trajectory as a one-off demonstration.

## Research object

- **World or environment:** Recoverable terminal workspaces reconstructed from file-operation histories, dependencies, and missing artifacts.
- **Agents:** Code agents, a completion agent, and a user agent that supplies later-round feedback.
- **Observations and actions:** Tool calls and file operations restore state; agents execute commands and receive verifiable execution feedback.
- **Goals and interaction protocol:** Replay the original intent, synthesize cross-workspace queries, and extend single-turn tasks into iterative sessions.

## What the paper does

The framework replays trajectory operations to recover each file before modification, fills gaps in the partial workspace, and then generates both the original task and variants. It scales breadth through dependency relations across workspaces and depth through simulated user feedback.

## Evidence and findings

The authors report 37.3k task-sufficient environments from public terminal trajectories. Supervised fine-tuning of Qwen3.5-27B on the resulting corpus is reported to improve Terminal-Bench 2.1 by 11.9 points and EvoCode-Bench v2 multi-turn MT@4 by 13.8 points. These are author-reported preprint results, not an independent replication.

## Reusable patterns

- Store executable state and provenance alongside the language trace.
- Turn one trajectory into a family of replayable tasks with controlled breadth and depth.
- Use a user simulator to expose requirement refinement rather than evaluating only first responses.

## Limitations and open questions

The setting is terminal/code-centric, so reconstruction may not transfer to social worlds with hidden beliefs, informal norms, or non-file state. Completion agents can also introduce artifacts that were not present in the source environment. Full corpus provenance and task leakage controls need inspection.

## Relation to this map

This is a strong data and environment pattern for the project’s executable-world goal: social episodes could likewise be recovered from event traces, then replayed under counterfactual dialogue, memory, or scheduling conditions.
