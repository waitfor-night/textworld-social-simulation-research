## 一句话要点

agent 的循环执行会把模型层的损坏转成系统层结果：agent 有时能从错误输出中恢复并完成任务，但代价是更高的计算与执行成本，少数故障仍会导致任务失败。

## 研究对象

- **世界或环境：** three agent benchmarks with 6814 executions
- **智能体：** LLM agents under random two-bit weight faults
- **观察与动作：** 随机两位权重故障注入后的执行轨迹、任务结果与计算成本。
- **目标与交互协议：** 在三个 agent 基准上共 6,814 次执行（2,400+ 干净运行、4,300+ 注入故障运行），注入独立采样的随机两位权重故障，并追踪故障在 agent 执行中的传播。

## 证据与发现

作者报告三个与既有研究不同的发现：（1）agent 能从故障输出中恢复并正确完成任务；（2）这种恢复会提高计算与执行成本；（3）少数故障仍导致任务失败。

## 可复用模式

可靠性评测不能只看任务成功率——需要同时报告成本；agent 的循环结构既是缓冲也是放大器。

## 局限性与开放问题

故障模型为权重级随机两位翻转；不涉及工具端或网络故障（后者见静默错误相关研究）。
