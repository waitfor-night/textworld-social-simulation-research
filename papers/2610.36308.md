## 一句话要点

记忆评测常把检索与生成合成一个分数，于是无法区分失败来自“漏掉更新”还是“检索到了更新却没用”；而实验显示后者是主因。

## 研究对象

- **世界或环境：** 6K-history FactConsolidation with 64 versus 512 token budgets
- **智能体：** Qwen2.5-7B and Qwen3-14B with BM25 retrieval
- **观察与动作：** 检索预算、检索到的证据，以及最终答案是否正确。
- **目标与交互协议：** 在 MemoryAgentBench 的单跳 FactConsolidation 任务上，用 Qwen2.5-7B-Instruct 与 6K 历史考察检索预算变化的影响；并用金标辅助的后验审计检查检索集中是否含最新陈述。

## 论文做了什么

把“漏掉更新”与“检索到更新却未使用”分开测量，并指出后者占多数失败。

## 证据与发现

作者报告 BM25 准确率在检索证据预算从 64 token 增到 512 token 时**从 45% 降到 32%**，而后验审计发现每个检索集里都含最新陈述——即失败主要不是检索问题。

## 可复用模式

“给更多证据反而更差”与 Computation Not Memory 的结论一致；对本项目的含义是上下文里放了什么，与角色是否使用它，必须分开测。

## 局限性与开放问题

单一任务与单一模型；长历史下的位置效应未完全分离。
