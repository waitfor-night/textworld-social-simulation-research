## 一句话要点

在终端类环境中，MCTS 式测试时搜索没有显著提升成功率：agent 的观察缺少评估所需的环境状态，中间状态也很少能预示最终成败。

## 研究对象

- **世界或环境：** terminal-based computer-use environments
- **智能体：** critic invoked only at claimed completion with forked state access
- **观察与动作：** 终端环境中 agent 可见的部分状态，以及 critic 对中间节点续展的排序能力。
- **目标与交互协议：** 分析 MCTS 配置下 critic 失效的两个来源；提出 Probe-and-Resume：只在 agent 自认为完成时调用 critic，并给它一台当前与初始状态分叉机的读/写/执行权限，让它探测以暴露轨迹遗漏的隐藏状态；被拒后 agent 从停止处继续。

## 论文做了什么

提出 Probe-and-Resume：把 critic 的调用时机从“部分进展中”改为“声称完成时”，并给它分叉状态的可执行访问权。

## 证据与发现

作者报告中间状态的 critic 排序只略优于随机，增加环境访问也改善有限；Probe-and-Resume 在 Terminal-Bench 2.1 上比常规 critic 的 MCTS 提升 8.4 个百分点，并以不到一半的成本接近同模型 Codex CLI agent 的成功率。

## 可复用模式

“只在声称完成时验证”对本项目直接可用：角色说做完了，World 才去核查，而不是在每一步都插一个评审。

## 局限性与开放问题

终端/计算机使用环境；分叉状态的权限在真实系统中可能不可得。
