## 一句话要点

任务状态仅显示给模型、由模型自记、转成指令或作为强制 gate，各有不同的失败条件；错误的 gate 甚至可能比不加 gate 更差。

## 研究对象

- **环境：** 两类动态任务，另对 τ²-bench 航空策略和 PM-Bench 进行迁移检查。
- **智能体：** 固定模型、规则和配对 episode；比较原始历史、精确 checklist、由执行收据推进的状态机指令与强制阻断 gate。
- **观察与动作：** 待办/取消/完成状态、执行收据和精确 payload。

## 论文做了什么

固定任务和模型，只改变权威任务状态到达 agent 决策环的方式，并用动态真值评分；特别检验 gate 的匹配器出错时是否伤害成功率。

## 证据与发现

作者报告：展示准确状态不必然可靠；模型自写未核验账本有时优于被动展示的准确列表；强制 gate 不依赖模型服从性，但准确性受状态机和动作匹配器限制。在 τ²-bench 某 235B agent 上，pass¹ 从 0.39 到 0.54；另一个 35B agent 无变化，PM-Bench 上甚至有 gate 伤害案例。

## 可复用模式

RoleAgent 保留请求/观察区别；World 依据结算回执维护任务真值。是否需要额外强制 gate，取决于能否可靠判断错误动作，并由配对 episode 验证。

## 局限性与开放问题

任务状态机可编译且部分目标可精确匹配；开放社会世界中“正确行动”常难以一刀切判定。

## 与本索引的关系

与 ActGov 和 World State Generator 一起约束 `请求→世界状态` 边界；反对为所有行动预设僵硬、可能误判的门禁。
