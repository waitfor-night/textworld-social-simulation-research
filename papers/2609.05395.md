## 一句话要点

KOPA-Bench 用真实韩国公共 API 检验多步工具链，EDGE 只保留实际执行成功的输出依赖，使合成轨迹可执行且能缩小开源模型与大模型的差距。

## 研究对象

- **世界或环境：** 韩国政府开放公共 API 及其相互连接的实时服务，包含 145 个真实任务。
- **智能体：** 链式调用工具的开源 LLM 智能体；另以同系列 9B 与 27B 模型比较训练效果。
- **观察与动作：** 每次工具调用读取真实 API 输出，并把可验证输出作为下一工具输入；EDGE 图记录成功的依赖边。
- **目标与交互协议：** 在 KOPA-Bench 和 BFCL 上完成多步任务；用实时执行遍历依赖图合成轨迹，再以 GRPO 微调。

## 论文做了什么

作者提出 KOPA-Bench 和 Execution-grounded Dynamic Graph（EDGE）：先实际调用 API，删除失败的工具连接，只沿验证过的边合成可执行多步数据，随后评估微调模型的工具链能力。

## 证据与发现

摘要报告，基于 EDGE 数据以 GRPO 微调的 9B 模型在 KOPA-Bench 和 BFCL 上几乎达到同系列未调优 27B 模型的表现。该结果支持“执行反馈过滤数据比静态拼接工具描述更可靠”的假设，但摘要没有给出具体分数。

## 可复用模式

- 把工具输出依赖表示为图，并以真实调用成功作为边的准入条件。
- 合成数据时保留完整输入、输出和执行记录，保证轨迹可重放。
- 在领域基准之外加入通用工具调用基准，检查是否真正学到链式执行。

## 局限性与开放问题

任务集中于韩语公共服务，实时 API 的可用性、版本和权限会影响复现；没有社会角色或多人协作行为，不能直接说明开放文本世界的规范遵守。9B 与 27B 的比较也需要跨供应商、离线快照和故障注入验证。

## 与本索引的关系

KOPA-Bench 是可执行工具环境与数据轨迹分支的核心条目，可与 TextWorld、ALFWorld 和安全上下文契约连接，为文本世界中的工具依赖验证提供工程模板。
