## 一句话要点

GameLogicBench 在每个 simulation tick 检查游戏规则，证明终局合法或视频看似正确仍可能掩盖运行过程中的规则违规。

## 研究对象

- **环境：** 72 个 Godot gameplay-logic 任务。
- **智能体：** 20 种模型与 scaffold 组合的 coding agents。
- **输入输出：** 代码修改、运行游戏、403 个手工场景和 1,451 个 seeded test case。
- **协议：** tick-level state assertions，并用删除必需能力的 mutant 验证 evaluator 能拒绝错误实现。

## 证据与发现

作者报告最佳运行解决 52.78% 任务；任务从孤立机制扩展到多系统和仓库级功能时，Claude Code 下全部 12 模型表现下降。未用 mutants 校验的 evaluator 会放过错误提交。代码公开。

## 可复用模式

交互式角色环境应在每个 tick 检查不变量，并用故意破坏规则的 mutant 验证测试确实能失败。

## 局限性与开放问题

任务是 coding agent 修改游戏逻辑，不是角色行为；tick assertions 的设计仍依赖人工规则覆盖。
