## 一句话要点

RSM-full 将在线 max-member merge 写入规则与 atom-aware grouped context packer 分开优化，针对约 2k–5k prompt token 的紧预算长程代理记忆质量—成本折衷。

## 研究对象

- **世界或环境：** AMA-Bench 和独立的 RealMem long-horizon persona-memory benchmark；代理历史以不断到达的文本记忆单元表示。
- **智能体：** 使用流式外部记忆的 LLM agents，比较 RSM-full、Online K-Means、Budget-RAG、BM25-RAG、Streaming-Proto 和 A-MEM 等记忆方案。
- **观察与动作：** 新消息按 cosine gate 与已有簇合并，查询时按原子边界组装上下文；代理使用压缩后的上下文回答任务。
- **目标与交互协议：** 在固定 token 预算下同时测量回答质量、token 成本和组件消融，并在另一 persona-memory 基准上复验。

## 论文做了什么

作者提出 RSM-full：用 max-member merge 保留簇中代表性记忆，再由 atom-aware packer 组合检索内容，避免把相关事实切碎或平铺拼接。实验覆盖多预算、多个随机种子和独立基准。

## 证据与发现

摘要报告 AMA-Bench 的 4k token 设置达到 Full-Context 质量的 83%，约使用 32% token；在约 2.6k–5k 区间相对 Online K-Means 提升 3.5–6.0 个百分点。RealMem 上相对 Budget-RAG 提升 0.69 个百分点，并显著优于 Streaming-Proto 与 A-MEM；作者同时强调高预算时其他方案可能更强。

## 可复用模式

- 把记忆写入合并和读取时上下文组装作为两个独立可消融组件；
- 以原子事实边界约束打包，减少跨事实截断；
- 报告质量、token 和预算区间，而不是只比较无限上下文下的准确率。

## 局限性与开放问题

优势集中在紧预算区间，不能直接外推到更大的上下文或不同记忆粒度；摘要未列代码仓库，AMA-Bench/RealMem 的任务和统计口径需进一步核验。尚未测试多角色私有信念、冲突更新或跨代理记忆权限。
