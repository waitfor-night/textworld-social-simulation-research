## 一句话要点

AEWM 不以编造工具返回为首要目标，而是判断哪些决策会污染任务状态，并在真实执行前修订下一步推理与行动。

## 研究对象

- **环境：** Search、Terminal 与 Software Engineering 的有工具反馈任务。
- **智能体：** 基于 Action Judge、State Revision 和 EditAct 的长程行动 agent。
- **观察与动作：** 历史观察、候选推理—行动对、真实工具结果。

## 论文做了什么

将决策区分为 critical、exploratory 和 noisy；对 noisy 候选从相同已观察历史编辑后续推理和行动，EditAct 将改动接入真实执行反馈；另对核验轨迹进行 rejection-sampling fine-tuning。

## 证据与发现

作者报告 Action Judge 宏 F1 为 70.5%，较最强被比对模型高 10.6 点；EditAct 在六个 benchmark、三个 agent backbone 上平均分提高 3.2–6.7 点。论文同时承认改写的是 agent 决策状态，不是直接模拟权威环境状态。

## 可复用模式

保留原始 World 观察与行动请求不变，仅允许纠正 Agent 从这些证据形成的暂定推断或后续候选行动。

## 局限性与开放问题

实验为搜索、终端与软件任务；不能直接推断关系、角色设定和社会世界动力学，也不应将编辑后的轨迹写回为已发生事实。

## 与本索引的关系

对 Clarification Is Not Correction 的任务状态污染给出可操作干预，但适用边界是 agent 侧状态，而非 World 权威事实。
