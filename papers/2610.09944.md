## 一句话要点

agent 能否按要求工作一段时间、预测自己会跑多久、事后估计已用多久——这三件事足以单独构成一个基准，而现有工作只测了“时间感知”。

## 研究对象

- **世界或环境：** 222 tasks from 18 sources spanning coding computer use agentic work and automated research
- **智能体：** agents in native harnesses such as Claude Code
- **观察与动作：** 实际墙钟耗时、请求时长与实际运行的偏差，以及事后对已用时间的估计。
- **目标与交互协议：** 在原生 harness 中运行 222 个任务，追加一条指定工作时长的指令（约一分钟到数天），比较请求时长与实际运行；再测运行前预测与运行后估计。

## 论文做了什么

提出 AgentTime：把“按请求时长工作（duration-following）”与运行时长预测、事后耗时估计分开测量，任务覆盖编码、计算机操作、agentic 工作与自动化研究。

## 证据与发现

作者报告按请求时长的准确性差异很大，例如 Claude Code 中的 Fable 5.1 相对请求时长有典型偏差；具体偏差数值需核对正文，本笔记不引用摘要以外的数字。

## 可复用模式

与时间相关的结论必须区分“知道自己跑了多久”“能按要求停下”“能预测将要跑多久”；这三者不能互相替代。

## 局限性与开放问题

评测面向长时运行的 agent harness，与本项目事件驱动、离散请求的世界时钟不直接对应；请求时长到数天意味着成本高昂。

## 与本索引的关系

补充既有关于世界时钟与调度时间的讨论：本次讨论的是 agent 侧对自己运行时间的感知与控制，而非世界时间。
