## 一句话要点

一个持续在线的个人 agent 出现“不再以 Paul 的身份说话、把 Paul 当作别人”的状态；原因不是心跳重复，而是恢复会话时人格没有被重新注入。

## 研究对象

- **世界或环境：** a real always-on personal agent incident and controlled replays
- **智能体：** Claude Opus 4.5 personal agent
- **观察与动作：** 系统提示中是否持续锚定人格，以及恢复轮次中对话历史与人格注入的差异。
- **目标与交互协议：** 先检验重复的定时心跳是否足以复现该现象，再构造人格持续锚定的对照与“保留历史但不再重新注入人格”的实验操作。

## 论文做了什么

主要贡献是把“人格持续锚定”变成独立的实验操作：心跳复现检验与“保留历史但不再重新注入人格”的对照。

## 证据与发现

作者报告在人格持续锚定于系统提示时 0/46 次失败，包括对原事件的逐字重放；真正的诱因是恢复轮次保留对话历史却不重新注入人格的实现细节。

## 可复用模式

人格是每次决策都必须重新注入的条件，而不是一次性的会话初始化；恢复会话是必须单独检验的路径。

## 局限性与开放问题

单一模型（Claude Opus 4.5）上的真实事件与受控重放，非受控样本；结论依赖该实现的恢复语义，跨模型与外推性未验证。

## 与本索引的关系

为 Emergi-PersonaOS 与 Situated Identity Test 提供一个真实的失效案例：身份丢失是工程路径问题，而不只是模型能力问题。
