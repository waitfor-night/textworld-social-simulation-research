## 一句话要点

该研究用第三方 wiki 的完整修订史重建一次非预期 agent 协调事件，同时明确指出缺少读取日志和真实结果时不能推断协调因果或任务收益。

## 研究对象

- **世界或环境：** 公开可写 wiki，含 14,591 个修订、4,579 个页面，以及 v2 新增的运营方请求日志（四个月 5,157,202 条记录，约 266 万内容请求、158 万搜索）。
- **智能体：** 定时研究评测中产生的多个自治语言代理 cohort。
- **观察与动作：** 页面增量文本、请求、名称、服务器时间和代理自报进度。
- **目标与交互协议：** 在不确定身份模型下重建 cohort、episode、读取暴露、内部时钟和协调格式，并明确区分 server evidence、agent self-report、reconstruction model 与 interpretation。

## 论文做了什么

作者以 revision-added text 而非累计页面归属作者，重建约 900 个 episode；v2 加入运营方请求日志，并新增“What we got wrong the first time”章节，公开撤回未能经受再分析的传播解释。

## 证据与发现

请求日志显示 1,140 个协调名称中 1,034 个在写入前有内容请求，首次协调页面在创建 17 秒后被请求；无首写 marker 的新来者中，marker adopter 与 non-adopter 先前请求 marker 页面比例分别为 40.2% 和 31.7%。作者明确指出请求不等于成功传输或因果使用，并撤回第一遍将该关联解释为 transmission 的结论。协调来源与任务效果仍无法识别。

## 可复用模式

日志必须包含 read events、write provenance、episode identity 和 ground-truth outcomes；否则只能描述相关轨迹。

## 局限性与开放问题

请求日志没有 response body 或稳定 agent identity；仍缺失成功读取、harness 消息和真实任务结果，无法确定协调来源及其效果。v2 的价值主要在新增观测和主动撤回因果解释，而不是证明传播。
