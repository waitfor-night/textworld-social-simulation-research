## One-line takeaway

Invalidation contracts attach version and cacheability metadata to remembered recovery advice so clients can evict only entries invalidated by server-side drift.

## Research object

- **World or environment:** Repeated API-recovery episodes across two domains and three serving paths, where cached fixes can become stale after data or schema changes.
- **Agents:** LLM planners, a client memory layer, and servers that emit versioned recovery suggestions.
- **Observations and actions:** The planner receives error observations and cached suggestions, decides whether to apply a fix, and receives deterministic validity metadata from the protocol.
- **Goals and interaction protocol:** Preserve useful cross-episode memory while separating protocol validity from model compliance and avoiding full re-derivation.

## What the paper does

The protocol adds version stamps and cacheability hints to each recovery suggestion. The authors decompose savings into validity (whether a cached suggestion remains correct) and compliance (whether a planner applies it on the first attempt), then compare row-level and coarse invalidation after drift.

## Evidence and findings

Across seven models and 9,432 episodes, the authors report deterministic validity, row-level compliance changes from 0 to 66.7 percentage points, 29–33% token-cost recovery for four models, and severe losses from table-level eviction. The paper also reports a 15% response-payload overhead, precision 1.00 for the validity contract, and model-specific schema conservatism; the linked server and client repositories make the protocol inspectable, but these remain single-preprint results.

## Reusable patterns

- Store provenance, version scope, and cacheability with every memory item.
- Measure validity separately from planner compliance and token savings.
- Prefer the narrowest invalidation scope that preserves unrelated memories.

## Limitations and open questions

The experiments concern API fixes rather than interpersonal facts or evolving norms, and row-level oracle invalidation may be easier than real social dependency discovery. The payload overhead, schema sensitivity, and behavior under correlated or adversarial drift need replication.

## Relation to this map

The protocol is an adjacent but practical building block for cross-episode social memory: identities, schedules, permissions, and norms can carry explicit invalidation scopes instead of being trusted forever or erased wholesale.
