## 一句话要点

失效契约为记住的恢复建议附加版本和可缓存性元数据，使客户端只驱逐确实受服务器漂移影响的条目。

## 研究对象

- **世界或环境：** 两个领域、三种服务路径中的重复 API 恢复回合；数据或模式变化会使缓存修复过时。
- **智能体：** LLM 规划器、客户端记忆层，以及发出带版本恢复建议的服务器。
- **观察与动作：** 规划器接收错误观察和缓存建议，决定是否应用修复，并从协议获得确定性的有效性元数据。
- **目标与交互协议：** 保留有用的跨回合记忆，将协议有效性与模型遵从分开，同时避免完全重新推导。

## 论文做了什么

该协议为每条恢复建议加入版本戳和可缓存提示。作者把节省分解为有效性（缓存建议是否仍然正确）与遵从性（规划器是否在第一次尝试时采用建议），并在漂移后比较逐行失效和粗粒度失效。

## 证据与发现

在七个模型、9,432 个回合上，作者报告确定性的有效性、逐行遵从率变化 0 至 66.7 个百分点，以及四个模型 29–33% 的 token 成本恢复；表级驱逐会造成严重损失。论文还报告响应负载增加 15%、有效性契约精确率 1.00，以及模型对模式的保守倾向。配套服务器和客户端仓库使协议可检查，但这些仍是单篇预印本的结果。

## 可复用模式

- 为每条记忆保存来源、版本作用域和可缓存性。
- 分别测量有效性、规划器遵从性和 token 节省。
- 在保留无关记忆的前提下，优先采用最窄的失效范围。

## 局限性与开放问题

实验针对 API 修复，而非人际事实或不断变化的规范；逐行的预言式失效也可能比现实中的社会依赖发现更容易。负载开销、模式敏感性，以及相关或对抗性漂移下的行为仍需复现。

## 与本索引的关系

这是一个相邻但实用的跨回合社会记忆构件：身份、日程、权限和规范都可以带有明确的失效范围，而不是被永久信任或整体删除。
