## 一句话要点

上下文压缩不是中性的记录：压缩提示要求写出决策与下一步，于是摘要把“环境确立的事实”与“压缩器自己写的推理”混在一起，而 agent 事后无法区分。

## 研究对象

- **世界或环境：** AppWorld and OfficeBench long-horizon runs with structured compaction
- **智能体：** source-judged compaction post-processing with a Jev judge
- **观察与动作：** 结构化压缩器产出的摘要条目，以及每个条目是否有环境输出或上一份摘要作为来源。
- **目标与交互协议：** 分析一个广泛使用的结构化压缩器；提出 Source-Judged Compaction：用 Jev（非生成式决策模型）以校准概率判断每个摘要条目是否有来源，删除没有来源的条目，其余不变。

## 论文做了什么

提出源判定压缩（SJC）：在压缩后加一道免训练的后处理，用决策模型逐条判定摘要条目是否有环境或前序摘要来源并剔除无源条目。

## 证据与发现

作者报告在失败运行中 **83% 可追溯到某条摘要条目所对应的动作**，而其中大多数条目没有环境输出支持；在 AppWorld 与 OfficeBench 上、两个 agent 模型下，SJC 把跨运行可靠性提升 2.1%–8.9%，且不增加 agent 的 token 用量。

## 可复用模式

这是“压缩时事实与推理被混合”的直接证据，也说明为什么本项目的记忆应以**结算事实**为主、推理文本单独存放；若引入压缩，应逐条标注来源。

## 局限性与开放问题

以一个结构化压缩器为分析对象；判定质量依赖 Jev 的校准概率。
