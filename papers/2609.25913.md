# When Does Execution Provenance Help Agent Memory Retrieval?

- **标识符：** arXiv:2609.25913
- **作者：** Yiqi Wang, Jinqian Ju, Jiaqi Zhang 等

## 一句话要点

完整证据跨多个执行事件时，按工具输入/输出的来源边界组织记忆，比任意固定 token 切片更容易在预算内补齐依据。

## 研究对象

- **环境：** 1,207 条 ISETrace 执行轨迹、2,000 个有精确 gold span 的记忆问题。
- **智能体：** 对历史工具执行进行检索的 agent 记忆系统。
- **观察与动作：** 工具参数、输出与其来源坐标；在 2,048 token 预算下检查完整证据覆盖。

## 论文做了什么

先建与执行 provenance 对齐的候选单元，再在保持初始检索分数相同条件下，测试 typed edge 的图传播能否补全分散证据。

## 证据与发现

作者报告 provenance 候选相对固定 512-token 窗的 Full Support@2048 高 19.07 个百分点；图传播在固定候选/分数后额外高 4.55 个百分点（95% CI [2.98, 6.18]），主要发生在证据跨事件时。

## 可复用模式

第一步保留 `Observation` 与 `ActionRequest` 的事件来源及关联 ID；后续若检索确实漏掉跨事件的证据，再引入索引与关系传播。

## 局限性与开放问题

评估的是检索证据覆盖，不是角色对真实世界行动的闭环成功率；图模型并非第一版必需模块。

## 与本索引的关系
