## 一句话要点

agent 评测只看两个数字：上下文窗口大小与最终答案正确率。两者都漏掉第三件事——工具输出在模型看到之前损失了多少。

## 研究对象

- **世界或环境：** 720 runs of a real tool-using agent reading Linux kernel traces
- **智能体：** agent harness with tool result truncation
- **观察与动作：** 工具结果是否被完整送达模型，以及被截断的结果如何影响后续。
- **目标与交互协议：** 在一个真实工具使用 agent（通过读 Linux 内核 trace 定位注入故障）上测量 720 次运行中的信息损失。

## 论文做了什么

提出“上下文是一条管道而非一个窗口”，并首次测量真实 agent 中的工具输出损耗。

## 证据与发现

作者报告上下文窗口几乎空闲——720 次运行中最大的提示只用掉 **5.75%** 的窗口——但全部工具结果中有**三分之一（11,189 条中的 3,827 条）在到达模型前被截断**，且每条被截断的结果都造成了后果。

## 可复用模式

这是对本项目最直接的一条工程警告：瓶颈不在窗口长度，而在管道中的截断与过滤；必须测量“工具输出到模型的保真度”。

## 局限性与开放问题

单一真实 agent 与内核 trace 场景；截断来源为实现细节。

## 与本索引的关系

与 ToolBottleneckBench（harness 预算主导失败）、Information Attrition 同属“失败发生在模型之外”。
