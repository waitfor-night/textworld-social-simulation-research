## 一句话要点

对 MCP registry 的概率抽样显示真实服务器大量无法启动，而常用工具基准的重复结构和可运行性与真实生态显著不同。

## 研究对象

- **世界或环境：** 24,135 个 MCP server 的 registry census、400 个 npm/stdio 随机样本及 BFCL v4、UltraTool。
- **智能体：** MCP 工具客户端和工具调用评测代理。
- **观察与动作：** 初始化握手、schema、safety annotation 和工具描述。
- **目标与交互协议：** 用公开 seed 对未修复样本实测，并与精选框和 benchmark corpus 比较。

## 论文做了什么

作者对 registry 做概率抽样并通过 wire protocol 探测，而不是先筛掉或修复不可运行 server；再统一计算工具描述重复率。

## 证据与发现

作者报告仅 48.8% 随机 server 完成初始化，37.5% 根本无法启动；运行工具没有致命 JSON Schema 违规，但 safety annotation 缺失率为 58.8%。BFCL 原始行有 68.8% 精确重复，UltraTool 为 85.6%，真实 MCP 为 0.4%。

## 可复用模式

工具生态评测必须报告抽样框、启动失败和全局去重；不要只在“能运行的精选工具”上估计能力。

## 局限性与开放问题

研究限于 npm/stdio 和一次 registry 快照；相似度分析主要是词汇层面。
