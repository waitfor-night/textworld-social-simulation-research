## 一句话要点

APEXA 用确定性工具层拒绝展示没有真实执行记录支持的结果，并按物理后果而非聊天质量分级评测科学设施 agent。

## 研究对象

- **世界或环境：** 同步辐射束线的数据校准与方位积分流程，包含异构计算和可选电机控制。
- **智能体：** 对外呈现单一推理循环的多智能体框架，调用 61 个工具。
- **观察与动作：** 自然语言任务、工具调用、真实执行证据、校准结果和受保护的设备动作。
- **目标与交互协议：** 58 个 facility task 的 APEXA-Bench、200 次模拟 IOC 对抗测试及真实束线数据演示。

## 论文做了什么

在工具层要求所有可展示结果都由已执行调用支持，并容忍不同模型的 tool-call 格式漂移；benchmark 用四级物理后果区分浪费计算和损坏仪器。

## 证据与发现

作者报告部署中的 frontier model 曾编造完整校准比较，实际命令并未执行；guard 将其转换为明确的 non-result。可选电机控制在模拟 IOC 上为 0/200 对抗违规，而等价 safety prompt 为 15/200。跨探测器 grading 还暴露两个潜在 pipeline bug。论文没有完成大规模 agent scoring；真实束线演示也不是总体可靠性估计。

## 可复用模式

事件日志中的“执行结果”必须由环境/tool receipt 生成；角色文本只能引用该证据，不能自行宣布动作已成功。

## 局限性与开放问题

篇幅为 workshop 版本，任务规模和部署统计有限；模拟 IOC 不能替代真实设备安全论证。公开仓库仍需单独检查实际代码、trace 与 benchmark 覆盖。

## 与本索引的关系

为 Authority、Narrative 和 tool execution 的分离提供部署案例，并补充 ERPBench、Cognitive Admission Control 与 GameLogicBench。
