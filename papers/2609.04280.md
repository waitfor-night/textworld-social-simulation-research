## 一句话要点

EVOHARNESSBENCH 把非平稳性放在工具、技能和 specialist-agent roster 组成的外部 harness 中，单独测量 harness 扩张造成的遗忘与持续适应。

## 研究对象

- **世界或环境：** 从 EnterpriseOps-Gym 与 Agentic Last Exam 等可验证基准构造的多阶段 harness 流；每个阶段累积新增工具、技能或代理能力。
- **智能体：** 使用外部工具、可复用技能和 specialist agents 的单代理或多代理系统，并可选择携带记忆、提示、代码或学习到的技能。
- **观察与动作：** 代理接收当前阶段的任务与累计 harness，进行工具调用、技能选择、代理委派或普通任务动作；自适应设置还可更新持久状态。
- **目标与交互协议：** 对比不携带跨阶段状态的 deployment evaluation 与携带状态的 self-evolving adaptation；用 forward transfer、backward transfer 和保留/适应指标分开报告结果。

## 论文做了什么

作者构造 17 条确定性的多阶段 harness 流，覆盖工具、技能和代理三个扩张轴，共 802 个任务、520 个工具、42 个技能和 62 个 specialist agents。任务使用 verifier-based 结果而非 LLM 生成的题目，使 harness 变化可以与任务内容变化区分。

## 证据与发现

摘要报告 harness 规模单纯扩大就可能降低先前已解决任务的表现（harness-induced forgetting）。自适应带来的新能力收益在不同阶段、轴和环境之间不稳定；保留旧能力与适应新能力也可能相互牵制。项目页进一步展示了 FWT/BWT/SAS 等分解，但具体数字应随项目版本锁定。

## 可复用模式

- 将外部能力集合的演化与代理内部学习分成两个循环；
- 对每个阶段固定 verifier，并同时报告新任务适应和旧任务保留；
- 把工具、技能、代理 roster 作为可替换的 harness 轴，便于迁移到文本社会世界。

## 局限性与开放问题

实验主要来自两个种子基准和受控、单调扩张的 harness 流，尚未证明在开放社会环境或会撤回能力的动态世界中同样成立。项目页与预印本的任务/版本入口可能继续更新；当前未在 arXiv 摘要中看到独立代码仓库，复现时应记录数据快照与 verifier 版本。
