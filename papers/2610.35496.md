## 一句话要点

随机删除旧轮次 75% 的 token 可能不损害 agent 效果，但原因、agent 如何补偿、以及是否真的省钱都不清楚。

## 研究对象

- **世界或环境：** 42 trajectory-reduction configurations in software engineering agents
- **智能体：** agents resending full trajectories each turn
- **观察与动作：** 42 种轨迹削减配置下的效果、agent 行为与成本。
- **目标与交互协议：** 系统改变删除的范围与粒度等维度，测量效果、行为与成本三方面。

## 论文做了什么

对轨迹删除做 42 种配置的实证研究，给出“隐藏成本”的度量与机制解释。

## 证据与发现

作者指出既有结论只表明“可能不损害效果”，但未回答为何、如何补偿与是否省钱（具体数值需核对正文）。

## 可复用模式

与 DeLoop、Prune the Summary 一致：压缩的代价常体现在行为改变与成本上，而不是分数上。

## 局限性与开放问题

软件工程 agent 场景；轨迹结构与角色对话历史不同。
