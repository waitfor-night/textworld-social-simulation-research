# 历史回填：文本环境谱系（2018–2021）

- **日期：** 2026-09-09
- **范围：** 执行 `docs/repository-development-plan.md` 批次 1
- **方法：** 从 autonomous/language-agent、role-playing 与 social-simulation 综述回溯共同引用的环境论文，再以 arXiv 规范页、论文 HTML 和官方代码仓库核验。

## 本轮新增

- [TextWorld](../papers/1806.11532.md)：可生成文本游戏、显式状态、转移与奖励，建立可控的泛化实验底座。
- [Jericho](../papers/1909.05398.md)：用人工互动小说补足生成环境的语言、常识与长程复杂度。
- [LIGHT](../papers/1903.03094.md)：首次把 persona、地点、对象、对话、动作和情绪系统地放入同一幻想文本世界。
- [ALFWorld](../papers/2010.03768.md)：把 TextWorld 高层动作与具身环境对齐，支持抽象策略向具体执行迁移。

## 形成的环境谱系

```text
TextWorld：可控生成 + 权威状态
  ├─ Jericho：人工世界的语言与常识复杂度
  ├─ LIGHT：身份、对话与世界动作共同 grounding
  └─ ALFWorld：抽象文本策略 ↔ 具体具身执行
        ↓
近期 LLM agent / belief-based world model / text world model
```

这四项工作共同说明，文本环境不是聊天记录：它至少需要状态、动作、转移、反馈和任务协议。LIGHT 进一步加入身份与局部社会上下文；ALFWorld 则显示抽象 rollout 和最终执行应分开评估。

## 对当前设计的影响

1. `World State Engine` 应维护独立于叙事文本的权威状态和动作合法性。
2. `Role Agent Engine` 的身份必须与地点、对象、关系和动作能力共同约束输出，不能只靠 persona 文本。
3. 世界模型评测应同时包含可控生成任务和人工复杂环境，避免只适配单一模板。
4. 高层计划成功、动作编译成功和底层执行成功必须分开计分。

## 第二批：架构与社会智能体基线

- [ReAct](../papers/2210.03629.md)：把推理、动作和环境观察组成可审计闭环。
- [Generative Agents](../papers/2304.03442.md)：用经历流、检索、反思和计划支持持续小镇生活。
- [SOTOPIA](../papers/2310.11667.md)：将角色背景、私有社会目标、人类参照和多维评分组合成互动评测。
- [Concordia](../papers/2312.03664.md)：以组件化代理和 Game Master 连接自然语言意图与生成式 ABM 环境推进。
- [CAMEL](../papers/2303.17760.md)：用角色提示与结构化对话协议实现早期多智能体协作。
- [Voyager](../papers/2305.16291.md)：把长期记忆落成可执行技能库，并利用环境错误迭代修正。

## 两批合并后的设计链

```text
显式环境状态（TextWorld / Jericho / ALFWorld）
  → 推理—行动—观察（ReAct）
  → 身份化语言与动作（LIGHT / SOTOPIA）
  → 记忆、反思、计划（Generative Agents）
  → 多角色通信（CAMEL）与可执行技能（Voyager）
  → 环境裁决与生成式 ABM（Concordia）
```

这条链为近期论文提供了更清晰的历史参照，但仍缺少系统性的综述/反证条目，以及 2024–2025 平台化、规模化和真实人类校准之间的过渡。

## 第三批：综述入口与可靠性反证

- [Autonomous Agents Survey](../papers/2308.11432.md)：规划、记忆、工具、应用和评测的宽口径引文入口。
- [CoALA](../papers/2309.02427.md)：用记忆、内部/外部动作与决策循环组织 agent 架构。
- [Role-Playing Language Agents Survey](../papers/2404.18231.md)：区分人口统计、既定角色和个体化 persona。
- [Social Simulation Survey](../papers/2412.03563.md)：区分个体、情景和社会三个模拟层级。
- [TrustSim](../papers/2410.23426.md)：表明角色模拟一致性与通用模型能力并不强相关。

综述只作为 taxonomy 和引文入口，不当作机制有效证据；TrustSim 则提供“更强模型不自动带来更可靠模拟”的约束。

## 角色扮演历史补充

沿角色智能体综述的引文继续补入 7 篇，形成更完整的演化链：

- [Persona-Based Neural Conversation Model](../papers/1603.06155.md)：隐式 speaker persona 与说话者—听者关系；
- [PERSONA-CHAT](../papers/1801.07243.md)：显式 profile 条件和众包人格对话；
- [ChatHaruhi](../papers/2308.09597.md)：从剧本抽取、检索角色经历；
- [RoleLLM](../papers/2310.00746.md)：角色知识、风格、指令数据与开放模型微调；
- [Character-LLM](../papers/2310.10158.md)：将人物 profile、经历和情绪变成可训练角色代理；
- [InCharacter](../papers/2310.17976.md)：通过心理访谈评测人格保真度；
- [LIFECHOICE](../papers/2404.12138.md)：通过文学人物决策点评测 persona-driven decisions。

由此得到的角色谱系是：

```text
隐式 speaker embedding
  → 显式 persona statements
  → 原作/经历记忆与检索
  → 角色条件训练
  → 知识与风格评测
  → 人格访谈评测
  → 决策一致性评测
```

关键结论是：角色扮演不能只用语言风格衡量。至少要分开角色知识、表达风格、人格、经历记忆、关系和行为决策；进入文本世界后，还需继续测行动后果和长期连续性。

## CoSER 与 Xintao Wang 研究线

[CoSER](../papers/2502.09082.md) 是这条角色研究线的中心节点：它从 771 本书整理 17,966 个角色，将场景、经历、原始对话、动作和内心思考组合成 given-circumstance acting 数据，并发布 8B/70B 模型和评测。

按研究问题而非简单作者列表追踪，其直接谱系为：

```text
InCharacter：心理访谈评测人格
  ├─ RolePersonality：用心理量表构造人格指示训练数据
  ├─ LifeChoice：用文学决策点测行为一致性
  └─ CoSER：文学场景 + 多角色表演 + 经历/内心
       ├─ ROLETHINK：检索经历、反应和动机，评测内心推理
       ├─ HER：在 CoSER 上加入双层思考、奖励模型和 RL
       └─ HumanLLM：把静态 persona 推进到多心理模式因果交互
```

另有 [MINDECHO](../papers/2407.05305.md) 将同一套个体化训练/检索思路用于现实 KOL；它有明确的同意、冒充、隐私和声誉边界，因此只列为 adjacent。作者同名检索会混入大量视频生成论文，本轮只收录能由共同作者、主题和引用链确认的角色扮演工作。

对文本世界项目最值得复用的不是一个更长 persona prompt，而是：将公开对话、私有内心、动作、经历记忆和权威场景分层；用多角色同场约束检验一致性；并防止同一文学数据在训练、检索和评测之间污染。

### 环境、工具与评测基础设施

- [ττ-Bench](../papers/2609.04611.md) 将业务记录、客户端模拟器、REST API、成本限制和继承代码库放入端到端 agent-construction 环境；作者报告最佳配置通过率 23.9%，专家参考上限 82.2%。
- [Harbor Adapters/Harbor-Index](../papers/2609.04298.md) 把 80 多个基准接到统一执行接口，并从 54 个基准筛出 82 个跨 29 个基准的高难任务；作者报告固定配置最高通过率 28%。
- [ERPBench](../papers/2609.04667.md) 用六轮 Solo/Arena 企业市场模拟区分固定规则对手与共享 LLM 生态；100 个问题中两种生态只在 21 个问题选出同一任务赢家。
- [EVOHARNESSBENCH](../papers/2609.04280.md) 把工具、技能和 specialist roster 的演化作为环境变量，拆出 forward/backward transfer 与 harness-induced forgetting。
- [MineExplorer](../papers/2605.30931.md)（v4）与 [GPTNT](../papers/2606.28514.md)（v2）分别覆盖 Minecraft 开放世界长轨迹和异步《Keep Talking and Nobody Explodes》协作；前者报告隐藏前置条件会伤害长轨迹，后者在完整异步设置下没有测试模型完成整局。
- [CUA-Universe](../papers/2609.05374.md) 与 [KOPA/EDGE](../papers/2609.05395.md) 把 GUI+CLI 状态和多步公共 API 依赖做成可执行环境；其训练/数据合成收益仍限于论文内基准与版本。

### 记忆、技能与持续状态

- [MemoryLACE](../papers/2609.03201.md) 显式保存 merge、supersession、contradiction 和 provenance；作者在 BEAM/StructMemEval 报告同 backbone 的总体优势，并称 BEAM 端到端运行时间较 Hindsight 少 66.6%。
- [Compact-Memory](../papers/2609.04915.md) 将在线 max-member 合并和 atom-aware packing 分开，在约 4k token 预算下报告 Full-Context 质量的 83%，使用 32% token。
- [KVMem](../papers/2609.04852.md) 把分页 KV 状态放在 GPU、主机内存和 NVMe 之间，目标是消费级 GPU 上的百万 token 工作区；[MemMA v2](../papers/2603.18718.md) 则把写入、检索、修复和回答拆成协作记忆角色。
- [Memory portability](../papers/2609.05339.md) 显示结构化 KG 表示在 writer swap 后较稳定，而自由文本 NOTES 对迁移方向敏感；这把“记忆是否可升级”从检索问题分离成构造、嵌入和恢复问题。
- [Trace2Tower](../papers/2609.05261.md)、[CoSkill](../papers/2609.04865.md) 和 [Persistent Skills](../papers/2609.04869.md) 都把轨迹变成可验证、可版本化的技能，而非无限追加摘要；其 ALFWorld/WebShop 或 OSWorld 数字仍是作者自报，需固定模型、轨迹切分和 verifier 后复现。

### 社会模拟、多智能体与 persona

- [Classroom](../papers/2609.05018.md) 在 20 个学生代理、15/50 天虚拟课堂中比较咨询 AI 的回应风格；论文明确这是内置模拟结果，不是人类心理效应测量。
- [CABAL](../papers/2609.05227.md) 的受控同行评审模拟报告共谋投标使目标论文捕获概率超过翻倍，并显示正投标图会被正常专业亲和度混淆。
- [Financial Markets](../papers/2609.04373.md) 把模型能力、代理数量和共享错误信息同时操控：准确共享推理可能降低风险，错误信息则把行为相关性变成系统性风险。
- [Testing Interchangeability](../papers/2609.05279.md) 发现角色互换对任务分数影响小，却使每单位进展的通信成本增加 16%–63%；更长历史和既有约定会放大漂移。
- [SCONPOS/PAS](../papers/2609.04676.md) 与 [Don’t Box Me In v2](../papers/2608.22411.md) 分别处理 persona 过度使用和动态文化混合；两者共同提示身份、关系、认知状态和表达风格不应压成一个静态标签。[中文语用基准](../papers/2609.04384.md) 的最佳 leave-writer-out 准确率 81.42%，仍低于人类 90.8%。

### 安全、失败归因与副作用

- [HarvestBench](../papers/2609.04444.md) 用有价格的绕行动作和确定性游戏日志计数动物碰撞；九个模型杀伤率为 0.4%–98.8%，morality briefing 会显著改变结果，但不代表开放世界道德可靠性。
- [Indirect Prompt Injection as Search](../papers/2609.04495.md) 把攻击发现视为受预算约束的测试时搜索；攻击者计算量是必须报告的测量条件，而不是可忽略的实现细节。
- [Semantic Overlays v3](../papers/2608.23873.md) 与 [HackProbe](../papers/2609.04665.md) 分别从表示标注和黑盒监测处理注入/奖励黑客；[DCFA](../papers/2609.04749.md) 则用全局依赖图加局部反事实定位多智能体失败。报告的 AUROC、攻击成功率和 step accuracy 都来自受控基准，不能当作真实系统风险率或因果识别保证。

### 跨论文模式

1. **Harness 是环境的一部分。** Harbor、EVOHARNESSBENCH、ERPBench 和 ττ-Bench 都表明，同一模型的结果会随工具、验证器、成本约束、对手生态和用户模拟器改变；索引记录应把 harness 版本与模型版本并列保存。
2. **持久状态需要生命周期。** MemoryLACE 的证据关系、portability 的 writer/reader 分解，以及 CoSkill/Trace2Tower 的技能晋升都把“写入—验证—替代—回滚”变成可测试协议，单纯增加上下文长度不是充分条件。
3. **协作收益伴随相关性成本。** 角色互换、金融错误信息和 GPTNT 的信息不对称共同提醒：代理数量或通信量上升不等于更好的社会行为，必须报告进展、通信、相关性和失败传播。
4. **可审计评测正在收敛。** 游戏日志、确定性断言、held-out 用户、human anchor 和轨迹级归因比单一 outcome judge 更可复现；但多数新工作仍缺少跨模型、跨种子和独立复现。

### 矛盾、缺口与下一步

- 能力提升与系统可靠性并不单调：金融模拟中的相关错误、HarvestBench 的模型间巨大差异，以及 ττ-Bench 的专家差距应在同一世界状态和预算下对照，而不是只排模型名次。
- 多数结果来自单一论文、封闭服务或小规模模拟；尤其 Classroom、CABAL 与 persona 工作不能直接解释现实群体或用户心理。下一轮优先固定公开仓库的 commit、数据 revision、模型配置和确定性回放。
- 下一步复现候选：Harbor/ERPBench/MineExplorer 的环境适配，MemMA/CoSkill/Skill-Evo4GUI 的状态与技能生命周期，Semantic Overlays/CONTINUITY 的安全链路；再把角色私有信念、互换、矛盾记忆和有价副作用组合进文本世界切片。
- 未见 2026-09-08 或 2026-09-09 新 arXiv 批次；下轮只在新版本、工件发布或独立复现改变可运行性时更新同一记录，避免重复建档。
